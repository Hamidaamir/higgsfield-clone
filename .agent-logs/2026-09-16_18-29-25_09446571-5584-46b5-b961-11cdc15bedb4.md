## 4. Architecture review — **keep the stack**, three small adjustments

Next.js + TS + Tailwind / FastAPI / PostgreSQL is right: it gives a genuine separation, FastAPI is the natural home for Python provider SDKs (Modal, Cloudflare), and all three have card-free free tiers. No change to the stack. Adjustments:

1. **Same-origin API via Next.js rewrites** (`/api/*` → FastAPI URL). Browser never talks cross-site, so httpOnly session cookies work without SameSite/CORS pain on Vercel↔Render. Dev-time: 0 extra; deploy: one env var; free-tier: none.
2. **In-process async jobs** (FastAPI `asyncio` tasks + DB status rows + frontend polling). No Celery/Redis. Video is inherently async at the provider (Modal `spawn` → call id), so a backend restart can resume polling from the stored provider job id.
3. **Neon instead of Supabase for Postgres, Cloudinary for media.** Supabase Free pauses the *whole project* after 7 idle days — a reviewer opening the link on day 8 would hit a dead app. Neon only scales compute to zero (sub-second resume). Cloudinary is card-free, CDN-served, handles video. Details in §9.

Everything else as you specified: modular monolith, one frontend, one backend, one DB, providers behind FastAPI.

## 8. AI architecture

```python
class GenerationJob(BaseModel):      # our model, never provider-shaped
    provider_job_id: str | None; status: JobStatus; progress: float | None
class ProviderResult(BaseModel):
    outputs: list[ProviderOutput]     # bytes | url, mime, width/height/duration
class ImageGenerationProvider(Protocol):
    async def generate(self, req: ImageRequest) -> ProviderResult | GenerationJob
    async def get_status(self, job_id) -> GenerationJob | ProviderResult
# VideoGenerationProvider / AudioGenerationProvider analogous
```

- `providers/registry.py` maps `model_id → (provider instance, provider_model_name)`; models config lives in `services/model_registry.py` and is served by `GET /api/models`. Adding a provider = one file + one config entry.
- **Job runner:** `generation_service.create()` inserts `queued`, debits credits, then `asyncio.create_task(job_runner.run(generation_id))`. Runner: set `processing` → call provider → if sync result: upload to storage, create assets, `completed`; if async job: store `provider_job_id`, poll provider with backoff up to model timeout → complete/fail. Failures: map provider errors to `error_code` (`provider_timeout`, `provider_error`, `quota_exceeded`, `content_blocked`), refund credits, never leak provider messages to the client. Startup reconciliation: `processing` rows with a provider job id are re-polled; without one (older than N min) are failed + refunded.
- Frontend `useGenerationPoll(id)` (TanStack Query, `refetchInterval` while active) drives progress UI; history invalidates on completion.
- Timeouts: image 90s, audio 60s, video 12 min (Modal cold start included).
